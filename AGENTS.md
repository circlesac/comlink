# Repository guidance

comlink is a front door that relays coding-agent clients to WebSocket agent endpoints — over SSH for the Codex desktop app, over stdio for ACP clients. A client that only knows how to reach a remote machine over SSH — today the Codex desktop app's SSH connections — runs `ssh <alias>`; the alias's `ProxyCommand` starts `comlink codex --stdio`, which speaks the server side of SSH on its own stdin/stdout, answers the few shell commands the client sends, and relays the agent protocol to a WebSocket endpoint. There is no sshd, no shell and no listening port. The Codex app discovers hosts through `~/.ssh/config`, so `comlink codex --server URL [--name NAME]` registers NAME (by default the first label of the server's host) as such a host for as long as it runs. For ACP clients, which launch their agent as a local subprocess when they need it, `comlink acp --server URL` is that subprocess and bridges its stdin/stdout to the remote agent's WebSocket; it ends with the client and needs no registration.

## Boundaries

- comlink does not implement any agent protocol. It recognises the command that opens an agent session and moves bytes between the SSH channel (or, for ACP, stdio) and the WebSocket. The protocol lives in the endpoint (for example a Cloudflare Worker that implements the Codex app-server protocol).
- Each supported client is a route: how its commands are recognised and which endpoint and framing its session uses. The Codex app is the first route. ACP clients (for example Zed) are the second client: they start the agent as a local stdio subprocess, so `comlink acp` bridges stdio to the WebSocket without SSH. Temple reaches endpoints over WebSocket directly and does not need comlink. Add a client by adding a route, not by special-casing the server.
- Commands are matched against what the client actually sends. Keep the captured commands under `test/testdata/` as the fixtures the tests run against, and refresh them from a real client when it changes (see README).
- An unrecognised command is logged to stderr and exits 127. It is never run.
- The upstream token is a secret: never print it, log it, or put it in an error. Read it from a file or the environment.

## Codex desktop app contract (ChatGPT.app 26.1023, Codex 0.165.0-alpha)

Verified 2026-10-28 by recording an SSH host the app connected to:

- The app runs system `ssh` with `BatchMode=yes`, the host alias from `~/.ssh/config`, and for the session also `-o ExitOnForwardFailure=yes -R 127.0.0.1:<port>:127.0.0.1:<port>`. The `tcpip-forward` global request must be accepted or ssh exits.
- Every command is wrapped: `sh -c '<login-shell launcher>' sh '<payload>'`. The payload is the last argument. It may start with `printf '%b' '<octal escapes>';` — a random marker the app reads before the real output; comlink must write those bytes to stdout first. It may continue with `PATH=...; export PATH;` and other setup that comlink ignores.
- Payloads and their answers:
  - `if command -v codex >/dev/null 2>&1; then exit 0; fi; exit 86` → exit 0.
  - `codex --version` → stdout `codex-cli <version>`, exit 0. The app refuses versions below its minimum; the reported version is configurable.
  - app-server bootstrap (contains `CODEX_SSH_SKIP_APP_SERVER_BOOT` / `app-server --listen`) → exit 0.
  - `pkill ... app-server ... --listen` → exit 0.
  - a payload ending in `exec codex app-server proxy` (possibly preceded by a remote-forward listener check and an ssh-agent symlink) → write the marker, then relay. On this route the client speaks WebSocket (HTTP Upgrade to `ws://codex-app-server/rpc`, then JSON-RPC text frames) over the channel; terminate that WebSocket locally and relay each message to the upstream WebSocket with `Authorization: Bearer <token>`.
- `subsystem sftp`, `shell` and `pty-req` are refused.

## ACP bridge contract

- The client runs `comlink acp --server <wss://host[/prefix]> [--token-file PATH]` as its agent command, which dials `<server>/acp` (see the server contract) without touching the session registry, and speaks ACP (JSON-RPC 2.0) on stdin/stdout, one message per line. The upstream serves ACP over a WebSocket with `Authorization: Bearer <token>`, one message per text frame (the remote-transport RFD).
- Each stdin line becomes one text frame without its newline (a trailing `\r` is dropped, empty lines are skipped, nothing is parsed, so a line that is not JSON is still sent). Each text frame becomes one stdout line followed by `\n`. Messages up to 64 MiB pass either way; a longer stdin line closes the upstream with 1009, and a binary frame from the upstream, or a text frame that contains `\n` or `\r` (the client would read it as several lines), is not written to stdout and closes the upstream with 1003; each logs one stderr line and exits 1.
- stdin EOF closes the upstream with 1000 and exits 0 once the close handshake completes. An upstream close exits 0 for 1000/1001 and 1 otherwise, without waiting for stdin. A failed connect is one stderr line naming the upstream without query or userinfo, and exit 1. A failed stdout write closes the upstream with 1001 and exits 1.
- stdout carries nothing but protocol lines; diagnostics go to stderr.

## comlink server contract

- A comlink server is one base URL (`ws://` or `wss://`, optionally with a path prefix) that serves the Codex app-server protocol at `<server>/codex` and ACP at `<server>/acp`, each a WebSocket with `Authorization: Bearer <token>`. The paths are joined onto the base whether or not it has a trailing slash or its own prefix (`wss://h/x/` and `wss://h/x` both give `wss://h/x/codex`). A server that supports only one protocol rejects the other when a client uses it; there are no flags to choose protocols.

## Codex sessions (`comlink codex`)

- Only the Codex app needs a registered session. `comlink codex --server URL [--name NAME] [--token-file PATH]` (`comlink codex` itself, with no subcommand) runs in the foreground until SIGINT or SIGTERM (stdin is not read) and then exits 0 having removed exactly the session files it created (the `~/.ssh/config` Include line below stays). NAME follows the alias rule (letters, digits, `-`, `_`, `.`); an explicit `--name` is used as is. Without `--name`, the base is the first DNS label of the server URL's host, lowercased (`wss://padawan.example.com/x` gives `padawan`, `ws://Worker:8787` gives `worker`), or `comlink` when the host is an IP literal (v4 or v6), `localhost` or `*.localhost`, its first label is `localhost`, or the label is not a valid alias: the Include line sits at the top of `~/.ssh/config`, so such an alias would capture the user's own `ssh` to that host. The session tries base, base-2, base-3, ... and takes the first candidate that is neither up nor has ssh configuration (below); when `Start` reports a candidate up (another session won it after the check) it moves on to the next. The ready output has a `name:` line: `padawan, the first label of the server's host (--name sets another)` when it took the label as is, otherwise `NAME (<reasons>; --name sets another)` with the reasons joined by `, ` in order (`the server host 127.0.0.1 is an IP address`, `padawan is already up`, `padawan has ssh configuration`). Termination is on a real signal, not a cap: candidates that are up are finite (one per running session), and two consecutive candidates that both have ssh configuration are taken as a pattern (for example `Host padawan*`) that matches every suffix, so the session fails with one line `"padawan" and "padawan-2" both have ssh configuration, so a pattern in it likely matches every padawan-N; pass --name NAME` before writing any session file. The Include line (below) is added at the first candidate without ssh configuration, before `Start`, so a refusal after a candidate that turned out to be up (`padawan` up, `Host padawan-*` matching `padawan-2` and `padawan-3`) comes after the line was added; a refusal at the first two candidates writes nothing at all. To tell whether the user's configuration already applies to a candidate, the session reads `~/.ssh/config` (the file comlink edits) and the files it Includes, and looks for a `Host` line with a pattern that matches NAME; it runs no subprocess. Lines are split the way ssh does: keyword in any case, separated from its arguments by whitespace or one `=`, arguments split like ssh's `argv_split` (on whitespace outside quotes, double or single quotes grouping, a backslash escaping a following quote or backslash, and outside quotes a space, and otherwise kept), `#` comments and blank lines skipped. The candidate is lowercased, as ssh lowercases the host it is asked for, and patterns match it as written, so `Host DEVBOX` applies to no name; `*` and `?` are the only wildcards; a `Host` line matches when some pattern without `!` matches and no `!pattern` does. A `Host` line that also matches a name made only of `/` characters, which no alias contains (`Host *`, `Host * !other`), applies to every host alike and does not count, so options under it never make a name look configured, while a pattern for comlink's own names such as `Host comlink-*` does count. An `Include` line is followed when it applies to the candidate, as ssh includes conditionally: at top level, under a `Host` line that matches the candidate (`Host *` too), and under a `Match` line (not evaluated, so its files count rather than go unseen); one under another `Host` line is not followed. `~` is the home directory (the parent of the config's directory), a relative path is relative to `~/.ssh`, globs expand, missing or unreadable files are skipped, a file already in the chain being read is skipped (an Include loop ends), Includes nest at most 16 deep like ssh's `READCONF_MAX_DEPTH`, and the session config files (anything in `<state>/comlink/ssh/`) are skipped, so a running or stale session never counts. It does not run `ssh -G`: ssh percent-expands options before printing (`ControlPath ~/.ssh/cm/%r@%h:%p`, `HostName %h.example.com` under `Host *` would make every name differ), runs `Match exec` commands and may do canonicalisation DNS lookups. Known gaps: `Match` blocks are not evaluated (an Include under one is followed) (they can run commands), and a short name that reaches a host only through DNS search domains has no ssh configuration; neither is detected. An explicit `--name` is not changed: a name that is up is refused (`session "NAME" is already up (pid N)`), and one with ssh configuration gets a one-line stderr warning `"NAME" already has ssh configuration (the Host line at <file>:<line> matches it); this session's Host block takes precedence while it runs` once it is up (a name that is refused gets the refusal alone). The token comes from `--token-file` or `$COMLINK_TOKEN` with the usual rules and warning. Several names can be up at once.
- State lives under `$XDG_STATE_HOME/comlink` (default `~/.local/state/comlink`): `run/NAME.json` (name, server, the `/codex` endpoint, pid; 0600), `run/NAME.token` (the token alone; 0600), `run/NAME.lock` (held with flock by the session process), `ssh/NAME.conf` (the `sshd.ConfigBlock` Host block whose `ProxyCommand` is `<exe> codex --stdio --name NAME`; 0600). Directories are 0700. The record, token and ssh config files are written through one helper: a temporary file in the same directory (named `<file>.tmp<random>`, matching neither `*.json` nor `*.conf`), mode set, then renamed into place, so ssh, the Codex app and `codex --stdio --name` never read a half-written file. The token is never in the record, the ssh config, stdout or stderr.
- Liveness is the lock: a record whose lock is held is up; one whose lock is free is stale, whatever its pid says (the kernel drops the lock when the session process dies, so a reused pid cannot fake a live session). A session on a name that is up fails naming the pid from its record (without a pid when the record is missing or unreadable, as inside `Close` or after it was deleted); on a stale name it removes the old files, says so on stderr and continues. `comlink codex list` removes stale records and reports them. `codex --stdio --name` does not remove anything: a name that is not up (no record, or lock free) is a one-line `session "NAME" is not up: ...` on stderr and a non-zero exit before any upstream is dialled. On builds without flock (not unix) liveness falls back to whether the recorded pid exists.
- A session prints the name, pid, server and the Codex alias on stdout, then `Press Ctrl-C to stop.`
- There is no setup command. Once NAME and the server are valid and before it writes any session file, a session makes sure `~/.ssh/config` has `Include <state>/comlink/ssh/*.conf` (the pattern double-quoted when it holds whitespace): when it is missing the session puts it at the top of `~/.ssh/config` (so it precedes any `Host`/`Match` block and applies globally), creating the file 0600 if missing, backing the previous content up to `<file>.comlink-bak` the first time it changes the file, keeping the rest byte for byte and the file's mode, writing through the same rename helper, and says so in one stderr line (`created <file> with "<line>"`, or `added "<line>" to the top of <file>` followed by `; previous content backed up to <backup>` when it wrote the backup); when the line is already there at top level (before the first `Host` or `Match` keyword; ssh applies an Include under a block only to that block) in any spelling ssh accepts it writes and prints nothing, and a line under a block does not count, so the line is added at the top as usual. When `~/.ssh/config` is a symlink (or a chain of them; relative links resolve against the real directory holding them), the links are left as they are and the file they finally name is the one read, backed up (as `<target>.comlink-bak`, next to the target) and replaced; a dangling link creates its target; a link loop is an error. The stderr line names both the link and the target (`<link> -> <target>`). When the line cannot be added (a link loop, an unreadable config, an unwritable file or backup) the session exits non-zero with one error line before creating any session file. The line is never removed: with no session up the glob matches nothing, so it has no effect.

## Command surface

- Commands are grouped by client. Codex app: `comlink codex --server URL [--name NAME] [--token-file PATH]` (the session; without `--name` it picks the first free name of base, base-2, ... and says which and why), `comlink codex --stdio (--name NAME | --server URL [--token-file PATH]) [--report-version V]` (one SSH connection on stdin/stdout: the `ProxyCommand` mode, which ssh runs and users normally never do; with `--server` it dials `<server>/codex`), and `comlink codex list`. The session and `--stdio` are `comlink codex` itself, which kong runs because it has a `Run` method even though it has subcommands; it owns its flags so `comlink codex --help` lists them, and no flag is tagged `required` because no flag is required in every form. `session.Flags.Check` enforces the combinations kong cannot express: without `--stdio`, `--server` is required, `--name` is optional (`session.Store.Up` picks a free one) and `--report-version` is refused; with it, exactly one of `--name` and `--server`, and `--token-file` only with `--server` (a session's token comes from the session). kong lets `list` inherit those flags, so it refuses them (`Flags.CheckUnset`), and it runs a parent's `Run` after its subcommand's, so `codex`'s `Run` returns at once unless `codex` itself was the command. kong's help writes `codex <command>`; `main.go`'s help printer corrects it to `codex [<command>]`. ACP: `comlink acp --server URL [--token-file PATH]`, dialling `<server>/acp`, with no `--name` and no registry. `--server` is always a comlink server's base URL. A new client gets its own command group. There is no top-level `up`, `list` or `ssh-include`, no `proxy`, `up` or `ssh-include` subcommand of `codex` (adding the Include line is part of the session) and no `--upstream`; they were never released, so there are no aliases. `sshd.ConfigBlock` renders the Host block.

## Conventions

- Go, one module, one binary. Pull requests are squash-merged into `main`.
- Layout: `main.go` declares the CLI and wires the packages, and stays thin because it is only run as a binary and counts as uncovered; `internal/sshd` is the SSH side and knows no client: it hands each exec request to a route and renders a `~/.ssh/config` block around a given `ProxyCommand` argument list; `internal/codex` is the Codex app route; `internal/acp` is the ACP stdio bridge; `internal/session` is the Codex session registry (paths, the atomically written record, token and ssh config files, the flock liveness, stale cleanup, adding the `~/.ssh/config` Include at session start, the static `~/.ssh/config` scan for a session name's `Host` lines, picking a free name when `--name` is not given), the flag checks of `comlink codex` and the bodies of the session, `list`, name resolution and the `--stdio` endpoint, taking writers so tests drive them in process; `internal/upstream` maps a server base URL to its `/codex` or `/acp` endpoint, dials the upstream WebSocket for both routes, redacts its URL in errors and loads the token. `internal/` holds no tests. All tests live in `test/` (one package, one file per subject) and reach the code only through its exported entry points or the built binary, mostly by driving `sshd.Serve` with the Codex route over a real SSH connection, `acp.Bridge.Run` over pipes, `session.Store` against a temporary directory, and the binary with a temporary `HOME` and `XDG_STATE_HOME`; nothing is exported or hooked for the tests' sake. Tests end on real signals (a ready line, a process exit, a close status), not on sleeps.
- `gofmt` and `golangci-lint` run in the test gate with `go vet ./...` and `go test -race -coverpkg=./... -coverprofile=coverage.out ./...`; CI fails when total statement coverage is below 80%.
- CI runs on `runs-on: ${{ fromJSON(vars.LINUX_RUNNER) }}`.
- No real personal or company identifiers in docs, tests or fixtures.
